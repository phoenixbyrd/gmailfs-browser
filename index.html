How GmailFS subjects are read

Subject format (from your screenshot + the original GmailFS / GMail Drive docs)

GMAILFS: /567081240_l.jpg [69610;a;1]

  • Path — everything between GMAILFS: and the […] block: /567081240_l.jpg. Folders come from the / parts of the path.
  • [size ; ? ; block] — first number is the declared file size in bytes (69,610 here — a plausible JPEG size), last number is the block number. A file bigger than Gmail's old attachment limit was split into several messages with block 1, 2, 3… — this browser groups messages with the same path, sorts by block, and joins the attachment bytes back together in order.
  • Data — the actual bytes are the email's attachment, not the subject. Opening a file downloads that attachment (or all its blocks) from Gmail and rebuilds the file in your browser.
  • Other variants — the original Richard Jones GmailFS stored directory entries, inodes and data blocks as separate messages with no filename in the subject. Those are also parsed: the attachment filename is used as the path when the subject has no path, and inode/block messages for the same file are grouped and joined.

If a subject does not match any known pattern it is still listed in the log below the scan, so nothing is silently dropped.
